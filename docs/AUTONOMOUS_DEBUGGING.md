# Autonomous Debugging 0.5 series

The Engineering Lab owns investigation workflow, not a duplicate failure classifier, test runner, or agent capable of modifying the game. Existing APEX-Simulation diagnosis/correlation and FAST/Test Lab, Development Lab analyzer and Lab Hub orchestration remain authoritative. ## 0.5.0
Create a private local registry folder outside checkouts. `python -m engineering_lab debug-open examples/debug-case.json --registry PATH` and `python -m engineering_lab debug-inspect --id BUG-DEMO-001 --registry PATH`. Exact target SHA, classification of observation, expected/observed symptom, bounded local evidence files and digest, immutable publication through registry.publish_once. Trusted local filesystem; not authenticated or tamper-proof. Observed failures require evidence; static or user reports are not confirmed failures. No inferred cause, test result or promotion.

Limits: two materialized hypotheses, one targeted attempt per candidate, 15 min lightweight workload, 1 MiB local file. Policy; no arbitrary execution. No permanent agent, new secrets, FULL, personal runner or game changes. Subsequent increments 0.5.1 classification/history, 0.5.2 reproduction, 0.5.3 solution proposal, 0.5.4 engineering memory. Each validated separately.

## 0.5.1

Register original correlation.json as case evidence, then `debug-classify --registry PATH --id BUG-ID --source correlation.json --case fixture.gd`. The existing game producer supplies classification, not this tool. `debug-history --registry PATH --fingerprint HASH` searches up to 1000 records and revalidates their evidence. Same fingerprint across commits is a recurrence lead, not the same root cause. Static signals and unverified user reports cannot be classified as observed CI failures. No raw log parser duplicated.

## 0.5.2

First register an existing v1 unit/fixture plan (candidate and baseline equal case SHA; explicit seed and command hash). Before recording any result, bind a JSON `{schema:1,id,case_sha256,experiment,plan_sha256,failure_metric,failure_value,fixture,budget_minutes}` with `debug-repro-bind INPUT --id BUG-ID --registry PATH`. Failure value must violate frozen criterion. Execute reviewed fixture via existing Hub/FAST or authorized offline test, register evidence via record, then `debug-repro-check`. Matching metric is an observation, not proof of same cause. Budget is declared, no external execution enforced here. `debug-repro-demo --registry NEW_PATH` actually runs a tiny deliberately defective arithmetic fixture; baseline FAIL is expected and recorded, CLI succeeds because workflow worked. No real game reproduction or arbitrary shell execution. Local file ledger is not authenticated or transactional across records.

## 0.5.3

Register one or two candidate v1 plans at distinct SHAs, same baseline, Lab SHA, repository, workload, criteria, kind and peer as reproduction. Before results, `debug-solution-bind INPUT --id BUG-ID --registry PATH` binds `{schema:1,id,case_sha256,baseline_result_sha256,hypotheses:[{id,statement,falsifier,files,experiment,plan_sha256,rollback}]}`. Candidate plans are authored by engineers/agents, not generated or applied autonomously. Record real reviewed test results via existing registry; `debug-solution-review` emits review dossier. PASS yields REVIEW_CANDIDATE only; no cause established, no game approval. `debug-solution-demo` actually executes corrected synthetic arithmetic expression after frozen failure. It does not modify real code. Candidate fixture equivalence and evidence authenticity require external review; local records not signed.

## 0.5.4

`debug-memory-record INPUT --registry PATH` accepts `{schema:1,id:MEM-ID,case:BUG-ID,lesson,tags,limitations}`. Captures validated case, optional classification, reproduction and solution snapshot; no overwrite. `debug-memory-read --id MEM-ID --registry PATH` revalidates the historical links and reports new evidence without replacing the snapshot. `debug-memory-search QUERY --registry PATH [--history research/debug-history.json] [--limit N]` performs bounded accent-insensitive AND text search; no ML. `debug-memory-demo --registry NEW_PATH` runs the synthetic lifecycle and saves a lesson. Open/unrun and adverse cases are legitimate memory; no automatic approval, deletion, correction or production integration. Local snapshots remain unauthenticated, not a tamper-proof ledger.
