# Encerramento de série — protocolo permanente

Obrigatório a partir da série 0.7. Não confundir com homologação esportiva, revisão científica independente ou branch protection do GitHub.

1. Congelar escopo, SHA, critérios e orçamento; revisar código/documentação e limites. Reproduzir falhas antes de corrigi-las e guardar execuções negativas.
2. Corrigir em PR isolada, manter critérios existentes e incluir testes de fronteira, regressão e cenários independentes. Achados OPEN bloqueiam o avanço, qualquer gravidade. LIMITATION é uma limitação de escopo declarada, não um defeito conhecido renomeado para liberar. Resolver ou registrar pendência sem avançar.
3. Confirmar QA, Physics Research Lab e Experimental Engineering no head exato e após merge main de árvore idêntica. Incluir novos workflows específicos de cada etapa como obrigatórios em ambos os conjuntos e ampliar REQUIRED por revisão quando existirem. Todos os três workflows leves agora executam em PR e push main. Nada de FULL, GPU ou runner pessoal.
4. Criar registro JSON audit/closures/<serie>.json depois das execuções. Campos: schema=1, series, next_series, candidate_sha, reviewed_main_sha, candidate_runs/main_runs (id, attempt, path), adverse_runs (mesmos campos mais sha), review (scope,boundary_cases,regression,evidence,documentation,rollback com descrição de revisão), findings (id,severity,status,summary,evidence), limitations (lista), rollback (procedimento). IDs AUD-*. Preservar resultados negativos relevantes; o gate confere os IDs declarados, não descobre todos os históricos.
5. Executar python -m engineering_lab closure-check audit/closures/0.7.json --managed usando credencial de leitura já disponível; offline bloqueia. Verifica live API, identidade do repositório/run/workflow/tentativa/SHA, sucesso dos dois conjuntos, falha dos adversos, main push, árvore e parentesco do merge. Não baixa logs/ZIP nem autentica parecer. Reexecução que altera attempt exige nova revisão de evidência.
6. Workflow Stage Closure Gate usa base SHA de PR/push, checkout exato e versão declarada. Mesma série sem alteração de registro não exige fechamento. Nova série exige sucessor do roadmap, registro da série anterior, revisão ancestral da base com diferença restrita ao próprio manifesto, e verificação ao vivo. Alterar código/testes/documentação depois da revisão exige renovar fechamento. Alterar registro exige validação. Nenhuma promoção automática.
7. Gate retorna BLOCKED/erro não-zero em falta, inconsistência ou credencial indisponível. Proteção obrigatória de branch precisa ser configurada pelo proprietário; esta entrega não altera permissões/rulesets. Aplicar revisão humana e não mesclar se o gate falhar. Reverter a PR do gate para rollback, mantendo histórico e política anterior.
